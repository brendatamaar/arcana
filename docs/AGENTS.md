# AGENTS.md

Instructions for AI coding agents (Claude Code and others) working in this repository. Read this file fully before making changes.

## What this project is

**Arcana** is a self-hosted, open-source sandbox orchestrator for AI agents, written in Go. It turns a Linux host with Docker into a service that creates isolated sandboxes (gVisor by default), runs commands with streamed output, transfers files, enforces resource and network limits, and later supports snapshots, forks, an MCP server and a read-only React web dashboard. Users install and operate it themselves.

## Source of truth

| File | Role |
|---|---|
| `PRD.md` | What to build and why. Requirement IDs (`FR-…`, `NFR-…`, `ESC-…`) are referenced everywhere. |
| `PLAN.md` | Task order, status, acceptance criteria, decision log, open questions. |
| `AGENTS.md` | How to work: conventions, commands, rules. |
| `docs/decisions/` | ADRs explaining design choices. |

If these documents conflict, **stop**, record the conflict in `PLAN.md` → Open questions, and ask. Never resolve a conflict by weakening a security requirement.

## Workflow

1. Open `PLAN.md`. Take the first task marked `[ ]` whose dependencies are all `[x]`. Mark it `[~]`.
2. Read the PRD sections the task references. Skim related ADRs.
3. Plan the change briefly (files, types, tests) before writing code.
4. Write tests alongside or before the implementation.
5. Run `make check`. If the task touches Docker, the runtime, exec, files, networking or reconciliation, also run `make test-integration`, and `make test-escape` when security behaviour could be affected. If it touches `web/`, `internal/webui` or `api/openapi.yaml`, also run `make web-check`.
6. Mark the task `[x]` in `PLAN.md` with a `> Done:` note. Update `PRD.md` and the Decision log if the design changed.
7. Commit once per task.

**Stop and ask** instead of guessing when:
- an acceptance criterion cannot be met as written;
- a change would relax any default in PRD §12 (security) or §8.1;
- a new dependency outside the approved list is needed;
- a spike result contradicts the PRD;
- you would need to change the public API shape in a way not described in PRD §10.

## Go conventions

- Go version: latest stable, set in `go.mod`. `CGO_ENABLED=0` must always build.
- Format with `gofumpt`; imports grouped stdlib / third-party / internal.
- Pass `context.Context` as the first parameter of anything that does I/O or may block. Respect cancellation.
- Errors: wrap with `fmt.Errorf("doing x: %w", err)`; define sentinel or typed errors where callers branch on them; map to API errors only in `internal/api`.
- No package-level mutable state. Construct dependencies explicitly and pass them in (simple constructor injection; no DI framework).
- Define interfaces where they are consumed, keep them small. `runtime.Driver` is the deliberate exception (shared contract).
- Logging only through `*slog.Logger` passed in; include `sandbox_id`, `exec_id`, `request_id` attributes where known. Never log API keys, env values, file contents or command output.
- Time: inject a clock interface in code with timers or deadlines (reaper, watchdog, TTL) so tests do not sleep.
- Goroutines must have an owner and a shutdown path. Use `errgroup` for fan-out.
- Keep functions short and names plain. Comments explain *why*, not *what*. Exported identifiers have doc comments.

## Frontend conventions (`web/`, from v0.3)

- React + TypeScript (`strict: true`), built with Vite, packages managed by pnpm with a committed lockfile (`pnpm install --frozen-lockfile` in CI). Node LTS.
- Function components and hooks only. Keep components small; one page per route under `src/pages/`, shared pieces in `src/components/`.
- Server state lives in TanStack Query. No global state library. Live data from `EventSource` updates the query cache rather than parallel state.
- All API calls go through the generated typed client in `src/api/` (`openapi-fetch` + `schema.d.ts`). No hand-written fetch calls to `/v1`.
- Styling with Tailwind CSS. No `<style>` or `<script>` tags in markup, and nothing that requires loosening the CSP.
- Never store an API key or session token in `localStorage`, `sessionStorage` or JavaScript-readable cookies. Login posts the key once to `/v1/sessions`, and the browser only holds the `HttpOnly` cookie.
- Treat everything from a sandbox as hostile: exec output, file names, labels, env keys and template names render as text. ANSI colour codes are parsed into styled spans.
- Accessibility: semantic elements, labelled controls, visible focus, keyboard navigation, WCAG AA contrast; light and dark themes from `prefers-color-scheme`.
- ESLint (with the React hooks and jsx-a11y plugins) and Prettier must pass. Watch the bundle budget (PRD §8.2) when adding packages.

## Security rules (non-negotiable)

1. **Defaults stay safe.** Default runtime `runsc`, network mode `none`, the hardening flags in PRD FR-RL-2. Any code path that would start a sandbox without them is a bug.
2. **runc requires opt-in.** Never remove or bypass the `allow_insecure_runtime` guard.
3. **No shell string building.** Commands are argv arrays. The only shell invocation is `/bin/sh -c <user-provided shell string>` when the API caller explicitly used the `shell` field.
4. **Host never touches workspace files.** File operations and snapshot extraction happen inside the sandbox via exec. Do not read from Docker volume paths on the host, do not use `docker cp`, do not extract archives on the host.
5. **Validate every path** with the shared path validator against `allowed_roots` before use.
6. **Every resource access checks ownership.** Non-admin keys get `404` (not `403`) for resources they do not own, to avoid leaking existence.
7. **Every new endpoint** is in `api/openapi.yaml`, goes through auth middleware (except `/v1/health`), has size limits on request bodies, and has tests for unauthorized and wrong-owner access.
8. **Every limit has a cap.** No unbounded reads, buffers, retries, goroutines per request, or result sets. Use `io.LimitReader` and pagination.
9. **Secrets:** store only key hashes; compare in constant time; write key files with `0600`.
10. **No `open` network mode** and no TLS interception in the proxy.
11. **Escape tests are never weakened** to make them pass. If one fails, fix the implementation or mark the task blocked.
12. **The dashboard stays read-only until T4.4.** A session cookie must never authorize a mutating request. Do not add write actions to the dashboard, or relax the cookie method restriction or `Origin` checks, without the CSRF design from T4.4.
13. **No HTML from untrusted data.** No `dangerouslySetInnerHTML`, `innerHTML`, `eval` or `new Function` in `web/`, and the CSP in PRD FR-WD-9 is never loosened.

## Testing

- Unit tests next to code, table-driven, using the fake driver and an injected clock. No Docker in unit tests.
- Integration tests use build tag `integration`, create real containers, and **always clean up** (use `t.Cleanup` with destroy). They choose runsc if available and runc otherwise, logging which.
- Escape tests use build tag `escape` and must assert both that the attack failed and that Arcana and a second sandbox remain healthy.
- Use `-race` for all unit tests. Avoid `time.Sleep` in tests; poll with a deadline helper when waiting on real containers.
- Coverage target ≥ 70% for `internal/` excluding generated code.
- Test names describe behaviour: `TestExec_TimeoutKillsProcessGroup`.
- Dashboard: Vitest + React Testing Library for components and pages, with MSW mocking the API. Every view that shows sandbox data has a test proving HTML in that data renders as text. Playwright runs one end-to-end smoke test against a real Arcana in CI.

## Generated code

- Never hand-edit `internal/api/gen/`, `internal/store/db/` or `web/src/api/schema.d.ts`.
- Never commit `internal/webui/dist/` contents (only its `.gitkeep`).
- Change `api/openapi.yaml` or SQL in `internal/store/queries/`, then `make generate` (and `make web-generate` from v0.3 when the API changed), and commit both source and generated output.
- Migrations are append-only once released: add a new migration rather than editing an old one.

## API changes

1. Edit `api/openapi.yaml` first.
2. Regenerate (`make generate`, plus `make web-generate` from v0.3).
3. Implement handler and tests.
4. Update `pkg/client`, CLI and (from v0.3) MCP tools, SDKs and dashboard pages if affected.
5. Update PRD §10 if the design changed.

Breaking changes to `/v1` after v0.1 require a Decision log entry.

## Commits and changelog

- Conventional Commits: `feat:`, `fix:`, `refactor:`, `test:`, `docs:`, `build:`, `ci:`, `chore:`, with an optional scope (`feat(exec): stream stdin`).
- Reference the task ID in the body (`Task: T1.10`).
- User-visible changes get a line under `## [Unreleased]` in `CHANGELOG.md`.

## Environment notes

- Linux with Docker ≥ 24 and cgroups v2 is required for integration and escape tests.
- Install gVisor for meaningful security tests: add gVisor's apt repository, install `runsc`, then `sudo runsc install` and restart Docker. `arcana doctor` reports whether it worked.
- On WSL2, Docker and runsc usually work; Firecracker is optional. On macOS use a Linux VM.
- Dashboard work needs Node LTS and pnpm (`corepack enable`). Nothing else in the repo does, and running Arcana never needs Node.
- Tests that need runsc or `/dev/kvm` must skip with a clear message when unavailable, never fail silently or pass vacuously.
- The LLM used by `examples/fix-agent` is configured through env vars (`FIXAGENT_BASE_URL`, `FIXAGENT_MODEL`, `FIXAGENT_API_KEY`); the default targets a local Ollama endpoint. Never commit API keys.
